### Request for Coding Agent

**System Context & Objective:**
You are an expert C++ and Python developer specializing in Multi-Agent Reinforcement Learning (MARL) environments. We are augmenting an existing high-performance, OpenMP-accelerated grid-world environment (currently in `craptop/src/batched_env.cpp` and `craptop/hide_and_seek_engine/env_wrapper.py`) as a Heterogeneous Search and Rescue (SAR) Simulator. 

The environment must strictly adhere to the PettingZoo API, support Hybrid Action Spaces, and be optimized for Centralized Training with Decentralized Execution (CTDE). The state and observation spaces must be structured as spatial tensors ($C \times H \times W$) to support CNN feature extractors.

**Core Mechanics to Implement:**
1.  **Verify Game Mechanics:** `test_level/tiles.json` includes new properties 'supports_x' where 'x' is in `[flying, walking, aquatic]` and blocking determines if the agent is blocked from entering the tile (therefore not stuck e.g. a wall) or allowed onto the tile (getting stuck e.g. water). These properties need to be verified for consistency throughout the codebase.
2.  **Level Rendering:** Each agent and tile have defined colors and positions in the state and observation space. The environment should be able to render from the global observation or any individual agent observation to verify operation.
3.  **Env Test Suite:** `env_spec.py` Needs to sucessfully load the attributes saved in test_level, perform unit and integration tests, and measure the frames per second for different numbers of parallel environments.
4.  **Human Data Recorder:** `human_runner.py` should run the test level with a single env where one of the agents is chosen at random to be controlled by 'WASD' and 1,2,3 radio controls. The state, action, reward, next state tuples need to be saved under `./saved_human_behavior/`
5.  **Write README.md** The environment behavior and basic usage in global and local mode including the observation and action space should be recorded in `README.md` for end user documentation.

#### Phase 1: Verify Game Mechanics (`env_wrapper.py`,`test_level/tiles.json`,`batched_env.cpp`)
- [ ] **Ticket 1.1: Implement `supports_x` tile properties.** Import supports_walking/flying/aquatic properly and adjust movement logic to allow any agent to pass that has at least one of the modes of transportation supported by a tile. 
- [ ] **Ticket 1.2: Implement tile blocking property.** Import the tile blocking property to decide if a tile lets an agent enter and get stuck if they do not posses the correct transport mode, or if the tile acts as a wall keeping the agent out and unstuck. 

#### Phase 2: Level Rendering (`hide_and_seek_engine/env_wrapper.py`,`batched_env.cpp`)
- [ ] **Ticket 2.1: Add Global Renderer.** Implement render() function in env_wrapper which draws each tile and agent according to their json color assignment in pygame. Globally undiscovered tiles should be rendered with their rgb values cut in half so that it is clear which areas have been explored. Saved survivors are colored full white.
- [ ] **Ticket 2.2: Add Local Renderer.** Implement render_pov() function which renders from a single agent's local pov. Allies are rendered in their last known locations and updated when they update via the radio. Survivors are only rendered if this agent is aware of them and they are rendered in the last state this agent knows about. 
- [ ] **Ticket 2.3: Add Radio Output.** Add radio_render() in batched_env.cpp which calles `std::cout<<` with any radio communications that frame.
